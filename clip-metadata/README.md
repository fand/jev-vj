# VJ clip metadata

ユーザーの `../clip-notes.md` に説明がある111項目だけを整理したデータ。
動画・ファイル名から内容を推測せず、説明文と会話中の訂正を根拠とする。API呼び出し・動画再解析なし。

| SELDO | 2 |

## ファイル

- `described-clips.md`: 記入済みの原文だけ。並び・ファイル名・原文を維持。
- `review.md`: 111本の原文、英語説明、設定できた属性、曖昧さの注記。
- `axes.md` / `axes.json`: 76評価軸の定義。今回値が得られたのは67軸。残る9軸は今後の記述用。
- `annotations.json`: 人が確認・修正する注釈。未記載の属性は省略。
- `metadata.json`: 全76軸を展開した保存用データ。不明はnull。原文・行番号・ハッシュ・派生属性も保持。
- `jev-candidates.json`: Jevに渡す候補データ。既知の属性と短い英語説明だけに絞る。省略は不明。
- `coverage.json`: 各評価軸が何本で判明しているか。
- `build.py`: 原文と注釈を照合して上記成果物を再生成する。意味解析を自動でやり直すスクリプトではない。

## 評価軸の分け方

色11軸、内容7軸、形状4軸、材質3軸、模様2軸、構図9軸、カメラ10軸、物体の動き13軸、光8軸、リズム5軸、技術特性4軸。

カメラ並進・カメラ回転・物体の動き・発光の速度は別々。例えばDucky3D 24はカメラslow、点滅medium。
Opti8はカメラslow、点滅fast。mantissa 052はカメラ並進fast、カメラ回転slow。
カメラ固定でも被写体は動く。物体が回転することからカメラ回転を設定しない。

主色・アクセント・背景・表面・発光・照明も分離。色の面積比や実測RGBは推定しない。
暖色/寒色/混合/無彩色は色名をまとめた派生分類で、`derived_attributes` に明示。
ピンク・紫など分類が一意でないパレットでは暖寒の分類を省略する場合がある。

## 解釈と不明値

- null・欠落は不明。「ない」「止まっている」「ランダムでない」などの否定とは違う。
- 元の文は常に保持。属性は人の説明を正規化したもので、動画を実測した事実ではない。
- 「半時計回り」は反時計回りに正規化。回転軸や時計回りを見る方向は原文以上に補わない。
- mantissa 001の「10くらいのスピード」は、ユーザーが会話で「中くらい」のtypoと訂正。mediumを採用。
- 「ミリアムスピード」「宙くらい」は文脈からmediumと解釈し、該当レコードで明示。
- 「島模様」「上振り」「超空砲体」「奥から手前から奥」など不明な箇所は属性を保留。
- 「おそらくシンプレックスノイズ」は仮説として注記し、確定タグにしない。
- 「ビートに合わせて光る」は見た目のビート表現。BPMやリアルタイム音声同期を意味しない。
- `*_alpha`という名前や透明チューブから、動画のalphaチャンネルを判断しない。
- 煙が太さ80%という記述から、占有面積80%や画面幅80%を数値として作らない。
- 繰り返す扉の内容と、ファイルの継ぎ目が見えないことは別。
- 音楽ジャンル適性・感情・ドロップ適性などは、このデータでは既成事実にしない。

## Jevでの利用

[TypeSafeのStateドキュメント](https://docs.typesafe.ai/concepts/state)に沿い、属性は判断の材料として渡す。
質問・評価基準は別に持つ。Jev向け説明とタグは英語、レビューと原文は日本語。

`pack_notes` はパック全体の自由記述。mantissaの「全体的に情報量多め」はここに保持し、各素材の密度へ一律に変換しない。

1. 現在のResolumeで再生可能な素材IDと照合し、候補を絞る。
2. ユーザーの指示と候補の既知属性をstateに渡す。全76軸のnullや原文を毎回全部送る必要はない。
3. 色・カメラ移動・物体速度・光の速度・内容などを必要に応じて個別評価する。
4. 最終選択には `keep` / `no_match` を含める。未記載の属性を「条件を満たした」と数えない。
5. 「ゆっくり」としか言われていない場合は、カメラ・被写体・点滅のどれかを勝手に固定しない。
6. 楽曲との相性や雰囲気は、音楽の状態と合わせた別の判断とする。素材固有の確定値と混ぜない。

例：「青系のトンネル、カメラはゆっくり、点滅は中くらい」ならDucky3D 24が根拠を持つ候補。
「時計回り」を求めるときはcameraとsubjectの対象を分けて照合する。
「金属＋白いビート状発光」ならOptiの該当候補を比較できる。

既存の `catalog.json` / Resolume操作は変更していない。素材IDは `pack/filename` の安定IDであり、
必ずしもサブフォルダを含む実ファイルパスではない。Resolumeのレイヤー・列番号との対応は別途必要。

## 再生成

```sh
python3 resolume-jev/clip-metadata/build.py
```

原文を変更した場合は、該当注釈の意味を再確認し、`source_note_sha256` も更新する。
原文の追加・削除・変更を検知した場合は古い注釈で生成せず失敗する。
外付けドライブは標準の生成に不要。`source_root` とファイル名を保持し、実パスは未検証。
実パスも探索する場合のみ `--resolve-paths` を付ける。未接続なら `unavailable` となる。
